## Problem / Context

This repo has no `.claude/notion.json`, so `notion-mcp.sh` / `notion-board.sh`
exit 3 and every ticket flow (tech-board-ticket read/create, /ship, /cleanup)
has to hand-resolve which board this repo files to. The board is in fact the
shared Tech Board and the project is the existing **"Portfolio 2026"** select
option. Declaring it once makes resolution automatic.

The resolvers (in `automation-scripts`) default the **server** to
`notion-freelance` and the **board** to the shared Tech Board when a repo
declares only a `project`. So the minimal correct config is `{ "project":
"Portfolio 2026" }` — no server, no board id to drift.

Safe-by-default: declaring only `project` means a board-id move can never go
stale here; the constant lives in one place (the resolver), not copied per repo.

## Plan

Add `.claude/notion.json` naming the project, guarded by a tiny validity test
so a typo in the project name (which would silently mis-resolve) fails CI.
